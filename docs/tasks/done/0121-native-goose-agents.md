## Implementation

Native Goose is available in standalone and ticket launch without ACP or container profiles. Fresh sessions receive unique CLI names; explicit resume/restart uses the actual saved Goose ID. Native initial prompts use literal --text= values, preserving even leading dashes. Foreground process/TTY/start discovery excludes servers/noninteractive runs; process arguments and unique names establish association, never open shared databases or latest timestamps. Running-session checks are scoped by database path as Goose IDs repeat between provider homes.

History uses bounded read-only SQLite queries (20 project candidates,100 rows/page, per-row/text limits, progress timeout), respects userVisible metadata, excludes reasoning/tools/other sessions, and accounts for active WAL updates. Receipts use per-session row positions and DB identity instead of file byte offsets. Native activity stays Unknown without a lifecycle feed; a separate exact empty editor/cursor and process-thread stdin-read guard permits requested queued messages. Native permissions/setup dialogs stay terminal-only; no automatic decisions. Existing close/restart guards and exact-session continuation remain. Updated OpenAPI, API/reference/operating docs and coordinator skills retire the initial container-only rule while keeping profile/container actions separate.
