# Agent workspace layout

Start agent, Find agents and Filters are the primary list controls. Search supports `/` to focus and Escape to clear. Filters opens a modal containing machine/project/status choices, All agents/Needs attention shortcuts, Refresh and All outboxes. Changes apply to the list immediately; Done/Escape closes the modal and restores focus. Filters shows the number of active non-search constraints. Clear filters leaves the visible search intact. Routine checked-at metadata lives in the modal; errors remain visible in the workspace.

On desktop, the active chat title sits in a full-width themed header with a slightly stronger background above the conversation, with Details and Open terminal on the same bar. Routine status/protocol badges live in cards and Details; approval, connection and work feedback remain in the conversation. There is one active conversation, not a new multiple-tab system. Details includes machine/provider/path, history association and process actions. Project-history browsing remains explicitly labeled. Context usage remains on agent cards; detailed context and token counters live inside Details for both native and ACP agents, leaving the conversation area clear. On compact clients, the original contextual header/back navigation remains; resizing moves the existing header/control nodes rather than duplicating them. Drafts, streams and process identities do not move to other agents.

Agent outbox in native chat Details is frozen to the exact selected agent process. All outboxes, reached through Filters, includes every process and exposes global bulk actions. These are distinct scopes despite sharing a component. Opening tools or modals does not acknowledge replies behind them, send messages, or authorize a bulk action. Existing explicit confirmation, one-use targeting and uncertain-delivery rules remain unchanged.

Machine availability in the navbar reports host errors only. Partial agent discovery alone does not raise a connection warning; the API retains its limited metadata for reconciliation without implying the machine is unavailable.

Cards use a full-width context meter with a right-aligned runtime label inside it and padding separating the labels (minutes, hours/minutes or days/hours), without adding a row. Native runtime starts at the verified CLI process; ACP runtime starts at the broker. Unknown shows an em dash; disconnected values are last-observed, not a running clock. These are process runtimes, not conversation age.

The card metadata row shows machine, harness / reported model, and project. Models come from process-associated provider metrics; unknown models are omitted. The row stays single-line with ellipsis and a full hover tooltip.
