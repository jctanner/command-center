# Agent token metrics

Agent cards show cumulative recorded session tokens and the last provider-reported context usage. Conversation **Token details** exposes input, output, cache read/write and reasoning counts when available. Missing values are `unknown`, including context capacity: CC never guesses from the model name. A context meter appears only when both usage and capacity are reported. These numbers do not establish Working/Ready, acknowledge replies or authorize input.

`QueueItem.token_metrics` and `Conversation.token_metrics` are nullable; the OpenAPI contract describes their fields. Cards require process-linked history. Explicitly selected project history can show counters in details, labeled Selected history. Disconnected cards retain counters as Last observed; timestamps refer to native reports separately from observation time.

- **Codex:** native `token_count.info.total_token_usage` is cumulative, never summed across snapshots. `last_token_usage.total_tokens` and `model_context_window` describe the last request. Cached input is included in input; reasoning is included in output. Compaction invalidates old context until a new report.
- **Claude:** native assistant `message.usage`, deduplicated and updated by `message.id`, supplies recorded session counts. Input excludes cache read/write; total is derived only when all four input/output/cache-read/cache-write fields are known. Context is the latest request's total, with unknown capacity unless explicitly supplied. Sidechains are excluded. Compaction invalidates context until a new report. Missing usage makes cumulative totals unknown rather than undercounting.
- **pi:** persisted assistant and auxiliary usage contributes to recorded conversation consumption, including abandoned branches. Context follows the selected native branch and becomes unknown across compaction/context/model changes until a new report. Missing usage or capacity remains unknown. This is raw recorded consumption, not the provider's edited or compacted context.

Reads reuse the existing local/SSH transport. Backend memory retains only numeric usage, native IDs/parent IDs, model names, timestamps and file cursor hashes; no message content or persistent transcript copy is created. Cache keys isolate endpoint, tmux target, action and conversation; file identity and rewrite checks reset old totals. Metadata cache capacity is 64 views, 4096 numeric nodes per view, with 30-minute idle eviction. Cold Claude/pi reads advance by at most 256 records and about 512 KiB per request (one record can extend the budget to 1 MiB). Unchanged files need only bounded prefix/cursor fingerprints. Codex reads a bounded 1 MiB tail when changed. Incomplete lines wait for completion; corrupt/oversized records or capacity exhaustion produce unknown totals. Very large logs can require several polls after backend restart. No whole-session rescanning on every poll, remote hook installation or provider configuration changes.
