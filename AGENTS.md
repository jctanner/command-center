# Command Center

## Purpose and scope

Command Center is a Rust backend with a web frontend for interacting with work across local and remote machines. It should become the everyday alternative to direct SSH + `tmux attach-session -d`; responsiveness and terminal correctness are core product requirements.

Build incrementally toward four capabilities:
1. Manage and interact with tmux sessions across machines.
2. Browse and edit files with syntax highlighting.
3. Maintain a Markdown knowledge base with raw-source editing, rendered editing, and a table of contents.
4. Show an agent task queue identifying agents in tmux panes that are waiting for quick human input.

The tmux milestone is implemented, including live machine settings. The next implemented slice adds machine-qualified project shortcuts and local/SSH file browsing/editing. The AI Queue is implemented as a separate workspace with live agents, conversation history, and explicit human messaging. Phone access over the existing private tailnet is now requested. Keep automatic agent responses, general LAN/internet exposure, and additional clients out of scope until requested.

## First milestone: focused tmux interaction

- Support configured local machines and SSH-accessible machines, including machines with multiple tmux sessions and sockets.
- Use a top row of machine tabs and a second row of window tabs for the selected machine/session. Provide a compact session selector when needed; disambiguate duplicate window names. Never flatten away tmux session identity.
- Display only the selected window's pane layout. Preserve selection per machine/session and use stable identities rather than names or window indexes as keys.
- Right-clicking a pane offers maximize/restore, equivalent to tmux's window zoom (`Ctrl-b z`). Target the intended pane explicitly, synchronize externally changed zoom state, and provide a keyboard/touch-accessible equivalent. Document that real tmux zoom can affect other attached clients.
- Provide interactive terminals, including keyboard input, paste, scrolling, resizing, colors, Unicode, and terminal applications. Handle focus and shortcut ownership deliberately so application shortcuts remain usable.
- Make connection, empty, loading, reconnecting, and failure states clear. A disconnected machine must not freeze other machines or the UI.
- Browser refresh or disconnect must leave tmux sessions and their processes running. Reconnect restores authoritative state. Do not silently detach other clients, kill sessions, or replay uncertain input after a transport failure.

Deliver a usable vertical slice: configure hosts, discover sessions/windows/panes, select a window, interact with its terminals, zoom/restore a pane, and recover from disconnects.

## Architecture

- Keep the backend in Rust. It owns connections, tmux inventory and commands, terminal streams, configuration, and shared state. Frontends must not execute SSH or tmux directly.
- Start with one backend service that supports local and remote tmux through a common transport boundary. Prefer deployment without a required remote daemon for the MVP; document any exception.
- Separate domain logic, tmux/SSH transport, API, and presentation sufficiently to test them independently. Avoid speculative microservices or a generic plugin framework.
- Expose a documented, versioned API for commands/state and a bidirectional streaming channel for terminal data and live events. Keep these usable by future TUI, native Linux/macOS/Windows, and iPhone PWA clients; do not embed essential behavior only in browser components.
- Distinguish durable configuration, observed tmux state, and client-local selection/layout. Scope identities by machine, socket, session, window, and pane as appropriate. Reconcile changes made by ordinary tmux clients.
- Choose and document a small web stack when implementation starts. Serve built frontend assets from the backend for normal use; a frontend development server is acceptable during development.

## Performance and terminal fidelity

- Use persistent SSH/terminal connections and incremental streaming. Avoid opening an SSH process per keystroke or using repeated pane screenshots/text captures as the interactive terminal transport.
- Investigate tmux control mode and PTY attachment against real terminal behavior before committing to a transport. Preserve terminal semantics, pane routing, and resize behavior; decide which client owns terminal dimensions when multiple clients connect.
- Subscribe to the active window's output; keep background discovery lightweight. Bound buffers and scrollback, apply backpressure, and cancel abandoned subscriptions. A noisy pane must not stall input or exhaust memory.
- Keep blocking work off async executors and rendering paths. Separate inventory refresh frequency from terminal output delivery; prefer events where practical and bounded polling where necessary.
- Measure before optimizing. Track input-to-visible-echo latency, window-switch latency, reconnect time, and idle/active CPU, memory, and bandwidth. Compare release builds with direct SSH + tmux on the same hosts/network. Establish explicit budgets from early measurements and record the environment and results.

## Safety and correctness

- Default to a loopback listener. Remote access must have an explicit authentication and encrypted-transport story before exposure. Validate browser origins for authenticated streaming connections.
- Respect SSH host-key verification and existing SSH configuration/agent practices. Never silently trust changed keys, expose private keys to clients, or log credentials and terminal contents by default.
- Use structured arguments and stable tmux targets. Treat names, paths, terminal output, and remote data as untrusted input; avoid shell interpolation and unsafe HTML rendering.
- Ordinary terminal input is user-directed. Future agent quick responses must bind to the current pane/prompt and reject stale targets; attention detection alone never authorizes automatic responses.
- File locations must be keyed by stable machine ID plus absolute path. The user explicitly wants arbitrary browsing within account permissions; project roots are navigation shortcuts, not access fences. Preserve file version checks, connection guards, and unsaved-change handling. Preserve Markdown source fidelity when introducing rendered editing.

## AI Queue

- Queue filters and selection are independent of terminal machine selection. Preserve the active terminal while viewing the queue.
- Show live Codex/Claude agents as well as attention requests; keep the badge focused on agents needing attention (pending approvals, unread replies, and unseen completion/approval changes). Inferred attention alone does not authorize input. Explicit approval cards may expose recognized live Codex/Claude menus after foreground-process verification; unsupported menus remain terminal-only.
- Conversation history must come from provider logs, separate from terminal context. Auto-link only with process evidence (validated PID/session registry, owned thread-writer lock, open log, or explicit session argument). Auto-select a sole candidate as project history; otherwise expose a machine/project conversation picker and label the association honestly; shared working directories never prove thread identity. Exclude reasoning, tool results, system/developer messages, and sidechains.
- Codex harness-injected interruption/environment context is not human chat or receipt evidence. Exclude only recognized content-item kinds with explicit harness provenance; retain literal human XML and ambiguous/mixed records. Keep structured interruption lifecycle events, native logs and reply cursors intact; version filtered history and invalidate stale cached pages.
- Explicit messages use expiring, one-use backend grants tied to machine connection, tmux target, foreground process start identity and fresh screen. Consume before transport IO, serialize with endpoint edits, reject replacement/stale input, and never retry uncertain delivery. Preserve drafts per agent process. Tool approvals require an explicit human choice with the original request and exact CLI labels/scopes visible. Bind expiring one-use grants to endpoint, target, process and screen, serialize with endpoint edits, and claim the prompt across clients before transport IO. Persist opaque submitted-prompt receipts before delivery; retain uncertain receipts and never retry automatically. Send only a verified single choice key, with no trailing Enter. Fail closed for unsupported menus or ambiguous repeated prompts. No automatic approvals or agent orchestration.
- Bound scanning and context, reuse SSH transport, report unavailable hosts, and discard observations when machine connection identity changes. Queue contents are transient and refreshed on demand. Read existing native history with bounded pages and version checks; do not create a separate copy of conversation history by default. Phone-friendly UI does not authorize network exposure or phone provisioning.

- Agent activity must expose state, evidence source and timestamps in the backend API. Only process-linked provider state can establish Working/Ready; selected project history and terminal silence cannot. Label terminal approval detection as inferred. Reject invalid/future evidence and expire old Working evidence to Unknown. Child-turn completion must not make a parent Ready.
- Retain recently disconnected agents briefly without refreshing their last-seen time, scoped to the unchanged machine connection. Browser queue failures must invalidate cached Ready states and disable sends. Existing status observation does not install hooks or change provider configuration.

- Attention/read metadata belongs in the Rust backend and must survive restart without copying conversation contents. Scope it by configured machine endpoint, process identity and conversation. Baseline existing history as read; never invent unread messages from user/tool-only log changes.
- Acknowledge only the exact observed event revision and assistant reply cursor. Old acknowledgements must preserve newer replies/events. Automatic previews, background tabs and older-history views do not mark replies read. Reading a notification cannot resolve an approval or authorize input. Keep an explicitly opened conversation visible when its card leaves an attention filter.

- Direct phone access uses the optional `--tailnet-listen` address validated against the local Tailscale CLI. Preserve the loopback listener and exact Host/Origin checks; the private tailnet membership/access rules are the access boundary. Do not silently broaden this to a wildcard listener or provision Serve/Funnel.

- Compact clients must default to AI Queue, hide Terminal and terminal handoffs, and never attach a viewer or send terminal WebSocket resize/input traffic. Explicit message/approval HTTP actions use guarded backend transport and must not resize panes. Apply this before startup and on viewport changes; resizing an attached browser into compact mode must detach its owned viewer. Keep the shared media-query policy aligned with CSS, including touch-device landscape. Verify with a simultaneous desktop client that compact navigation leaves tmux dimensions and original processes unchanged.

- Treat compact AI Queue as a conversation interface: edge-to-edge messages, a compact contextual header, metadata behind Details, and a docked growing composer. Keep list filters collapsible and preserve list/draft/read state across navigation. Validate visible-viewport/keyboard changes, landscape, and actual message-area proportions rather than checking only that controls exist.

- Keep live work feedback visible in the conversation, including compact mode. Distinguish verified provider Working state, a local waiting-for-reply hint after a successful send, unavailable status, and disconnection. Never imply token streaming from completed log messages or mark local waiting as backend Working. Poll only the selected visible conversation faster while active; preserve drafts and terminal dimensions.

## Launching agents

- Start agent in AI Queue uses the same machine-qualified pinned/discovered projects as Files, plus manual directories. A project is a machine and canonical directory; never invent a separate queue-only inventory. Pinning is explicit and uses the existing revision-checked config API.
- Human launch preparation binds an expiring single-use grant to endpoint revision, canonical directory identity and installed Codex/Claude/pi executable identity. Resume requires an explicitly selected, still-valid project conversation UUID; reject a known running conversation. Never pass arbitrary commands, CLI flags, approval bypasses or guessed session IDs from clients.
- Default to a dedicated detached tmux session at a fixed initial size; an explicitly selected existing session may receive a new detached window instead. Bind its stable session ID and server/session creation identity into the grant, reject vanished/replaced/private viewer sessions, and preserve existing selection, pane dimensions and processes. Remain-on-exit preserves startup errors. No mobile terminal viewer is attached. Complete CLI authentication/trust prompts through the provider's normal interface; never approve them automatically.
- Keep the launch UUID and endpoint fingerprint before IO. Recovery is read-only, survives page/backend restart, and must reject a changed machine endpoint. Never retry an uncertain launch automatically; check the existing session first. A separate launch requires explicit user intent.
- For newly launched agents, do not auto-associate unrelated sole-candidate project history. Explicit resume/session arguments or verified owned writer locks establish identity. When supported, Codex uses its owned server via --no-daemon; bounded parent/start-verified child writer locks may establish that launched process's conversation.

- Launch model overrides are optional validated literal identifiers, bound into preparation grants. Blank means no --model flag; preserve harness defaults and saved resume behavior. Provider/machine changes reset the model field. Never accept arbitrary CLI options as a model.

- Terminal management must let a configured machine create its first detached tmux session, including when no server exists, and offer window renaming through both tab right-click and keyboard context menu. Bind mutations to endpoint revisions and source session/window IDs, reject stale names/membership, preserve pane processes and other clients, and invalidate inventory after mutations. Names/directories are literals: escape tmux format syntax as well as using structured local/SSH arguments. Never automatically retry an uncertain creation.

- SSH machines may specify an optional literal `ssh_jump` destination/alias. Apply it through shared transport for inventory, PTYs, files and agent actions; do not implement a nested interactive shell or forward the SSH agent. Enforce noninteractive authentication and strict host-key verification on both hops. Jump-route edits change connection identity and invalidate pending grants/read scopes, while direct-host identities remain backward compatible.

## Native pi agents

- Discover exact `pi`/`pi-coding-agent` foreground commands, including Node processes whose title is `pi`. Verify process/start identity before granting any message input; do not match unrelated commands such as pip or ping. Preserve native launch behavior and existing pi processes.
- Read native pi v1–v3 JSONL sessions from the provider home/session directory, validating header cwd. Follow the latest persisted v2/v3 id/parentId branch; exclude abandoned branches, system/thinking/tool/custom records and incomplete writes. Bound reads, page visible messages, and reset client history when the persisted branch changes. Raw history is not the provider's compacted/edited model context.
- Open session files, explicit session arguments or a fresh process-verified native bridge record can establish association. A directory, newest timestamp, terminal silence or latest assistant stop reason cannot establish the running pi session or live Working/Ready state. Label unverified project history and live status honestly. Multiple project conversations require a choice; a sole candidate may auto-select as unverified project history.
- Pi uses the existing single-use process/screen/endpoint-bound message transport. Recognized selection dialogs block ordinary messages; arbitrary extension dialogs are not approval capabilities. Install the passive Command Center pi bridge only when explicitly requested. Do not restart agents, switch to RPC, or invent approval responses to support observation.

- The native launcher supports pi with optional --model and explicit --session file resume. Preserve provider directory overrides and single-use launch guards; fresh pi launches keep native session creation and do not auto-link old project history.

- Window renumbering inserts at a requested index and shifts only the intervening windows by one. Guard the endpoint and observed session window IDs/indexes, target links by session plus stable window ID, preserve processes and active selection, and never use replacement (-k) or automatically retry uncertain reordering.

- Desktop notifications are explicit browser opt-in, with per-process mute controls, privacy-preserving event text, bounded opaque browser receipts and cross-tab Web Locks deduplication. Baseline existing attention, consume muted/already-read events, validate endpoint/process identity on click, and open the observed conversation ID. Never auto-request permission, infer pi activity, send agent input from notifications, or claim browser-open polling is iPhone/background push delivery.

- The explicitly requested native pi bridge publishes metadata only (process start/boot, session file/ID/leaf, heartbeat and lifecycle state). Validate owner/private file permissions, PID/start/boot, pane/cwd and freshness before association or status. Use agent_settled, never agent_end, for Ready; ui_prompt events report terminal-only input without approval capabilities. Never collect message content, install hooks into another extension, or reload/restart a live agent automatically.

- Clipboard ownership: preserve Shift-drag selection under application mouse reporting and keep hover from erasing a local selection. Ctrl+Shift+C copies, Ctrl+Shift+V uses native browser paste, and Ctrl+C without selection remains an interrupt. Menu clipboard reads require an explicit gesture and revalidate the live generation/host/session/window/pane after awaiting permission; inactive-pane menu paste stays disabled. Preserve bracketed paste and never append Enter or retry uncertain input.
- OSC 52 application clipboard writes are bounded, UTF-8 only, opt-in and accepted only by a visible focused terminal. Ignore queries; never expose host clipboard contents to terminal output. tmux set-clipboard is server-wide: show that scope and require an explicit revision/expected-mode-checked settings action. Do not enable it automatically, edit tmux configuration files, or log/store clipboard payloads.

- Window/pane creation uses explicit source session/window/pane IDs and observed cwd plus endpoint revision. Default to the source directory, accept a literal absolute override, validate it is enterable before mutation, and escape tmux formats in paths/names. Create detached shells without arbitrary commands; the requesting client selects the new window/pane. Splitting restores the full layout from zoom. Preserve other clients’ selection and existing processes; uncertain creation is never retried automatically. Offer pane actions through right-click and keyboard context menu on footer pane controls.

## Workspace navigation

- Workspace tabs use canonical hash routes (`#/terminal`, `#/files`, `#/queue`, `#/slack`, `#/email`, `#/board`). Apply the initial route before host discovery or terminal creation. Tab clicks push history only when the route changes; reload, hash changes and Back/Forward restore the workspace without duplicate entries. Programmatic workspace handoffs must update the route too.
- Keep routes limited to workspace identity: do not serialize drafts, prompt text, credentials or action grants into URLs, and never replay launches/messages/approvals from navigation. Existing machine/window selection and component drafts remain independently scoped. Unknown routes fall back to the device default. Compact terminal routes normalize to AI Queue before attachment, including viewport changes. Defer lazy Files setup until host metadata is ready.

- Window-tab Close window requires explicit confirmation showing the machine/window, pane count, shared session links and any last-window session closures.
